# AGENT:24 — 포지셔닝 재정의 & 슬라이드 플로우

## 1. 왜 재포지셔닝이 필요한가

심사위원 메모 2가지:
1. 자원을 최소한 쓰며 최대 아웃풋을 내는가
2. 특정 업무에 최적화되어 있는가 (범용보다 나음)

기존 프레이밍 "학술-산업 갭 탐지"는 **무엇을 찾아내는가**에 초점이 있어서, 이 두 기준과 직접 연결되지 않음.
새 프레이밍 "리서치 워크플로우 최적화"는 **같은 결론에 도달하는 비용을 얼마나 줄였는가**에 초점을 맞춰서, 심사 기준 문장을 거의 그대로 발표에 쓸 수 있음.

**핵심**: 기능/파이프라인은 하나도 안 바뀜. "무엇을 만들었나"의 설명 프레임만 바뀜.

---

## 2. Before / After

| | Before | After |
|---|---|---|
| 한 줄 정의 | 학술과 산업 사이의 갭을 찾는다 | 기업이 신기술을 검토하는 시간을 최적화한다 |
| 서사 축 | 발견(Discovery) | 절약(Efficiency) |
| 증명 방식 | "이런 갭을 찾아냈다" | "수백 개 문서를 몇 분 만에 걸러냈다" |
| 이름 후보 | Research-to-Reality Radar | Research-to-Reality Radar — *Technology Validation Workflow Optimizer* (부제로 유지) |

이름 자체는 안 바꿔도 됨. 부제/한 줄 설명만 "Optimizing Technology Validation Workflow"로 교체.

## 3. 기존 파이프라인 → 최적화 요소로 재라벨링

발표에서 각 단계를 소개할 때 "이게 왜 최적화인가"를 한 문장씩 붙이면 됨. 새로 만들 것 없음.

| 단계 | 원래 역할 | 최적화 관점 재설명 |
|---|---|---|
| Scope Calibrator | 검색 범위 좁히기 | 불필요한 검색을 애초에 실행하지 않음 → API 호출 자체를 줄임 |
| Scholar Scout | 학술 근거 수집 | 사람이 논문 수십 편 읽는 시간을 대체 |
| Vocabulary Bridge | 동의어 매핑 | "다른 이름으로 같은 기술 다시 검색"하는 중복 낭비 제거 |
| Adoption Scout | 산업 도입 사례 수집 | 사람이 뉴스/블로그 일일이 찾는 시간을 대체 |
| Gap Candidate Generator | 후보 생성 | 여기까지 결과를 근거 기반 **우선순위**로 압축 |
| Adversarial Verifier | 반증 검토 | 잘못된 우선순위에 낭비될 후속 검토 비용을 사전 차단 |
| Conditional Deep Research | 조건부 심화 검토 | 비싼 API를 "꼭 필요할 때만" 씀 — 이게 바로 "자원 최소, 아웃풋 최대"의 가장 직접적인 증거 |
| Evidence / Adoption / Coverage 3점수 | 신뢰도 표시 | 불필요한 재검토를 줄이는 의사결정 보조 |

**발표 포인트**: "우리는 새로운 정보를 생성하지 않습니다. 이미 존재하는 방대한 연구를 가장 적은 비용으로 가장 빠르게 검토하도록 리서치 과정을 최적화합니다." — 이 문장을 슬라이드 3(에이전트 개요) 마지막 줄이나 발표 오프닝 멘트로 배치.

---

## 4. 슬라이드 5장 플로우 (확정안)

룰: 슬라이드는 팀소개·배경용, 최대 5장, 2분 배정. 제품 설명은 라이브 데모(3분)+서프라이즈(2분)가 증명.

### Slide 1 — 팀 소개
- 팀명, 팀원 2인 역할(프론트/백엔드)
- 트랙: Liner API Agent (Track 03)
- 한 줄: "Research-to-Reality Radar — Technology Validation Workflow Optimizer"

### Slide 2 — 문제 배경 (Why)
- 기업/리서처가 신기술 검토에 쓰는 시간 문제 제시
- "수백 개 논문 + 산업 자료를 사람이 직접 읽어야 함" → 병목 지점 명시
- 여기서 **심사위원 메모 문장을 그대로 인용/변형**해서 문제 정의에 녹이면 좋음: "특정 업무에 최적화된 도구가 범용 도구보다 낫다"는 전제를 이 슬라이드에서 깔아둠

### Slide 3 — 에이전트 개요 (What)
- 6.5단계 파이프라인 아키텍처 다이어그램 (Scope Calibrator → Scholar Scout → Vocabulary Bridge → Adoption Scout → Gap Candidate Generator → Adversarial Verifier → Conditional Deep Research)
- 각 단계 옆에 "최적화 포인트" 한 줄씩 (위 표 활용, 너무 많이 넣지 말고 3~4개만 강조: Scope Calibrator 불필요 검색 제거, Vocabulary Bridge 중복 제거, Conditional Deep Research 조건부 실행)
- 마지막 줄: "우리는 새로운 정보를 생성하지 않습니다. 가장 적은 비용으로 가장 빠르게 검토합니다."

### Slide 4 — 왜 Liner인가 (Why Liner)
- Liner Search API(Web/Scholar 분리)가 파이프라인 1·2단계의 핵심 근거
- Deep Research Agent API가 "조건부 심화 검토"를 가능하게 하는 핵심 — 여기서 실측 데이터(예: 단순 질의 ~59초) 언급하면 "실제로 써봤다"는 신뢰도 상승
- Liner 없이는 이 최적화 구조 자체가 성립 안 된다는 점을 명시 (스폰서 트랙 심사 포인트)

### Slide 5 — 아키텍처 / Raw API Stream 안내
- 실제 데모에서 보여줄 화면 구성 예고 (Gap Map + Raw API Stream 병렬)
- 데모 입력 예시 살짝 티저
- "지금부터는 슬라이드가 아니라 라이브로 증명합니다" 멘트로 전환
