# 결선 데모 시나리오 (7분: 슬라이드 2분 + 라이브 데모 3분 + 즉석 태스크 2분)

> 규칙 브리핑에 명시된 원칙: "시나리오를 외우는 대신, 실제로 범용적으로 작동하는 파이프라인을 만드세요."
> 이 문서는 대사를 암기하라는 대본이 아니라, (1) 제출용 2분 데모 영상과 라이브 데모에서 쓸 **좋은 예시 주제**를 정하고 (2) 어떤 입력이 오든 항상 통하는 **나레이션 포인트**(왜 이 순서로 도구를 부르는지)를 미리 준비해서 실전에서 말이 막히지 않게 하는 용도다. 즉석 태스크는 정의상 각본을 쓸 수 없으므로, 그 2분은 "무슨 입력이 와도 이렇게 반응한다"는 행동 지침만 정리한다.

## 0. 지금 당장 확인할 것 (제출 전)

1. **파이프라인 전체 실행 시간을 실측**했는지 확인 — 라이브 데모는 3분인데, 여러 단계(scholar_scout → vocabulary_bridge → adoption_scout → gap_candidate → adversarial_verifier → conditional_deep_research → gap_map)를 순서대로 도니 실제로 몇 초/몇 분 걸리는지 한 번도 재본 적이 없다. 지금 바로 타이머 켜고 3~5개 주제로 돌려서 평균/최악 시간을 재야 한다.
2. 3분 안에 안 끝날 것 같으면 **빠른 모드(fast mode)를 라이브 데모 기본값으로 켜두는 걸 강력 추천**한다 — 시간 예산 내에서 잠정 결과("부분 판정" 안내)라도 반드시 나오게 만든 기능이 이미 있으니, 데모가 타임아웃으로 멈추는 최악의 시나리오를 막아준다.
3. 두 화면(발표용 노트북 + 세컨드 화면) 연결을 미리 테스트: 메인 화면 `?view=user`, 세컨드 화면 `?view=stream`(또는 `?clean=1`).

## 1. 슬라이드 2분 (최대 5장)

이 문서 범위 밖(팀 소개/문제 배경까지만, 제품 설명은 전부 라이브 데모)이지만 순서만 잡아두면:
1. 팀 소개 (10초)
2. 문제 배경 — "연구는 많은데 산업 적용은 왜 안 될까" (경쟁 브리핑에서 강조된 "Impact 20%"에 대응, 실제 사례 1개로 임팩트 체감시키기)
3. 에이전트 개요 — 파이프라인 구조 다이어그램 1장 (Scholar Scout → Vocabulary Bridge → Adoption Scout → Gap Candidate → Adversarial Verifier → Deep Research → Gap Map), "왜 이 순서인가"를 한 줄씩
4. (남으면) 지금까지 발견한 흥미로운 결과 스크린샷 1장

## 2. 라이브 데모 3분 — 추천 예시 주제

**예시 주제: "학생 리포트 표절을 자동으로 잡아주는 서비스"**

이미 실사용 테스트로 검증된 입력이라 안전하다. 산업 아이디어를 그대로 입력해서 preflight가 "텍스트 표절 탐지(plagiarism detection)"라는 실제 기술명으로 자동 변환하는 걸 보여주는 게 핵심 — Prompt Quality(20%)와 Pipeline Architecture(25%)를 동시에 증명한다: "산업 문제를 그대로 던져도 시스템이 알아서 학술 검색 가능한 형태로 바꾼다"는 게 이 프로덕트의 차별점이기 때문.

예비 대안: 이미 갭이 뚜렷하게 나오는 걸 확인해둔 다른 주제(예: 최신 임베딩 기반 기법이 상용 서비스엔 아직 없는 케이스) — 위 예시가 당일 결과가 흔들리면 즉시 대체.

### 타임라인

- **0:00–0:15** — "왼쪽이 저희 제품 화면, 오른쪽이 지금 이 순간 실제 호출되는 API 요청을 가공 없이 그대로 보여주는 Raw API Stream입니다."
- **0:15–0:35** — 입력창에 "학생 리포트 표절을 자동으로 잡아주는 서비스" 타이핑. "일부러 학술 용어가 아니라 산업 문제 그대로 입력했습니다. 저희 사전 검사 에이전트가 이걸 실제 검색 가능한 기술명으로 바꿔줍니다."
- **0:35–0:50** — 제출. 세컨드 화면에서 `input_preflight` 이벤트 → `auto_corrected` 판정, 화면에는 "'학생 리포트 표절을...'에 대한 검색결과가 없어 '텍스트 표절 탐지(plagiarism detection)'에 대한 결과를 표시합니다" 문구 뜨는 순간을 짚어준다.
- **0:50–2:10** — 파이프라인이 도는 동안 세컨드 화면 이벤트를 하나씩 짚으며 "왜 이 순서인가"를 말로 채운다:
  - scholar_scout: "먼저 학술 근거부터 찾습니다"
  - vocabulary_bridge: "학술 용어를 그대로 산업 검색에 쓰면 안 걸리니, 별도 에이전트가 산업 검색어로 한 번 더 바꿉니다"
  - adoption_scout: "바뀐 검색어로 실제 산업 도입 사례를 찾습니다"
  - gap_candidate_generator: "두 근거를 대조해서 갭 후보를 판정합니다"
  - adversarial_verifier: "판정을 내리기 전에, 일부러 반대 증거(이미 산업에 쓰이고 있다는 증거)를 찾아서 스스로 반박을 시도합니다 — 성급한 결론을 막는 안전장치입니다"
  - (조건부) conditional_deep_research: 뜨면 "근거가 부족하거나 상충되면 조건부로 심층 조사까지 갑니다"
- **2:10–2:50** — 결과 화면: 판정 라벨(앰버=갭 발견), 스코어 카드 3개, "연계된 근거/진짜 갭/연계 가능성" 3갈래, 마지막 "이런 기회가 있습니다" 제안까지 짚는다. "저희는 관찰에서 안 끝내고 구체적으로 뭘 만들면 되는지까지 제안합니다."
- **2:50–3:00** — 전환: "이제 심사위원님이 아무 주제나 주시면 같은 파이프라인이 그대로 작동하는 걸 보여드리겠습니다."

## 3. 즉석 태스크 2분 — 각본이 아니라 대응 원칙

무슨 입력이 와도 아래 셋 중 하나로 자연스럽게 이어진다. 이걸 팀원끼리 미리 입으로 한 번씩 말해보는 연습만 하면 된다 (실제 문구를 외우지 말 것):

- **모호하거나 너무 넓은 주제** → preflight가 `needs_calibration`으로 걸러 추천 검색어를 보여줌. "저희 시스템이 스스로 '이 주제는 너무 넓다'고 판단하고 구체적인 방향을 역제안하는 걸 보여드립니다" 라고 말하면 오히려 강점으로 전환됨.
- **완전히 무의미하거나 주제가 아닌 입력** → `rejected`로 조기 차단, 크래시 없이 안내 문구만 뜸. "예상 못한 입력에도 죽지 않고 항상 응답합니다."
- **산업 문제/아이디어 형태의 입력** → 슬라이드에서 보여준 것과 동일하게 자동 기술명 변환이 실시간으로 다시 일어남. 데모에서 이미 본 동작이 재현되는 걸 짚어주면 "일회성 시연이 아니라 실제로 범용적으로 작동한다"는 걸 증명하게 됨.

시간이 빠듯할 걸 대비해 **즉석 태스크 시작 전에 빠른 모드를 켜두고 시작**하는 것도 팀 내 합의해두면 좋다.

## 4. 역할 분담 제안

- 1명: 입력 타이핑 + 결과 화면 설명
- 1명: 세컨드 화면(raw stream) 나레이션 전담 — 이벤트 이름이 뜰 때마다 "왜"를 말로 채움
- 1명: 시간 관리 + 즉석 태스크 대응 시 백업(네트워크 이슈 등 발생 시 즉시 개입)
