### 심사위원(OpenAI) 비공식 코멘트 반영 사항
- 랜덤성을 어떻게 정형화하느냐 + 최소 자원으로 최대 아웃풋을 내는지를 중점적으로 본다 (평가셋을 계속 돌릴 시간이 없다는 전제)
- 특정 목적에 좁게 최적화된 에이전트가 범용 에이전트보다 아웃풋·비용 면에서 효율적 (승용차 vs 특수차 비유) — 워크플로우 자체가 좁고 명확하면 충족되며, 도메인을 억지로 좁힐 필요는 없다
- 오케스트레이터(큰 모델)-워커(작은 모델) 분리 권장: 큰 모델은 플래닝/판단, 작은 모델은 실행(쿼리 생성, 요약)
- 셋업 파일(AGENTS.md/CLAUDE.md)을 미리 준비하면 반복 프롬프팅이 불필요해지고 효율이 체감 10%가량 오른다는 언급
- 발표자료는 "AI가 만든 티"가 감점 요인 — 타이틀케이스 금지, 번역투/마케팅 톤 금지, 엔지니어 매뉴얼 톤 권장
- 역할분담이 중요: 팀원 중 디자인/발표자료 전담 1명을 반드시 배정하라는 권장 → 강지호가 이 역할

## 3. 타겟

> 우리의 에이전트 타겟은 최적화이다. 다른 여타 에이전트보다 이 업무에서는 이 모델이 더 나아야 한다.

"특정 목적에 최적화된 좁은 워크플로우"로 해석한다. 도메인(주제)을 좁히는 게 아니라, 수행하는 판단 로직 자체를 하나로 고정하는 방식으로 충족한다.

## 4. 컨셉 — Bridge Agent

한 줄 정의: 이 에이전트는 새로운 것을 만들지 않는다. 이미 존재하는 학술 근거와 산업 도입 증거 사이의 불일치를 찾아, 추가 조사가 필요한 "적용 갭 후보"를 정직하게 판정하는 리서치 에이전트다.

- 출력 톤은 창작/제안이 아니라 탐지·판정으로 끝까지 유지 (Creative Agent 트랙과 경계가 흐려지는 것을 방지)
- "창업 아이템 후보" 같은 창작 뉘앙스 단어는 쓰지 않고 "적용 갭 리포트", "근거 불균형 판정" 식으로 통일

타겟 유저: 연구 주제를 정해야 하는 대학원생/연구자, "이 기술 왜 아직 안 쓰이지?" 궁금한 실무자
도메인: 특정 분야로 한정하지 않음 (범용 유지 — 서프라이즈 태스크 대응력 확보를 위한 의도적 선택)

### 트랙 부합 근거
| 키워드 | 대응 |
|---|---|
| 학술 검색 | Scholar Scout 단계 |
| 리서치 | 학계 vs 산업 대조·판정 (단순 검색이 아닌 비교·추론) |
| 지식 워크플로우 | 입력 → 범위판정 → 학계탐색 → 산업탐색 → 갭생성 → 반증검증 → (조건부)심층검증 → 시각화 |

### 채택 근거
- Liner API 4개 이상(Search×2, Deep Research, Visualization)을 다층적으로 사용 → "API 하나만 우려먹음" 리스크 없음
- 승격 로직(1차 스캔 → 조건부 심층검증)이 "랜덤의 정형화" + "최소자원·최대아웃풋" 기준을 구조적으로 만족
- 밈/논쟁 팩트체크류(할루시네이션 캐처 등 해커톤 단골 소재)를 의도적으로 피해 참신성 확보

### Track 01 (Creative Agent)과의 차별화
Track 01 정의에도 "리서치 워크플로우 자동화"가 들어있어 경계가 흐려질 수 있다. 대응:
1. Liner 고유 구조(Scholar/Web 분리)를 승급 로직의 근거로 명시 — 다른 검색 API로 대체 불가능함을 보여준다
2. 데모 화면에 "지금 Scholar 엔드포인트로 탐색 중" 같은 라벨을 노출한다
3. 출력 톤을 "탐지·판정"으로 고정하고 "창작/제안" 뉘앙스 단어를 제거한다
4. 슬라이드에 "이 에이전트는 만들지 않는다, 판정한다"를 명시한다

## 5. 포지셔닝 — "리서치 워크플로우 최적화" 프레이밍

심사위원 메모 2가지(자원 최소·아웃풋 최대 / 특정 업무 최적화)에 발표를 직접 연결하기 위한 재프레이밍이다. 파이프라인과 기능은 그대로이고, 설명 방식만 바뀐다.

| | Before | After |
|---|---|---|
| 한 줄 정의 | 학술과 산업 사이의 갭을 찾는다 | 기업이 신기술을 검토하는 시간을 최적화한다 |
| 서사 축 | 발견(Discovery) | 절약(Efficiency) |
| 증명 방식 | "이런 갭을 찾아냈다" | "수백 개 문서를 몇 분 만에 걸러냈다" |

오프닝 (Slide 1→2 전환): "저희는 새로운 리서치 결과를 만들어내는 에이전트가 아닙니다. 이미 존재하는 방대한 연구와 산업 자료를 가장 적은 자원으로 가장 빠르게 검토하는, 리서치 워크플로우 최적화 에이전트입니다."

클로징 (Slide 5→데모 전환): "말로 설명하는 대신, 지금 이 순간 몇 개의 API 호출만으로 무엇이 최적화되는지 직접 보여드리겠습니다."

## 6. 슬라이드 5장 플로우

1. **팀 소개**: 팀명(지성)·역할(정윤성 발표, 강지호 디자인)·트랙(Liner API Agent)·한 줄 정의
2. **문제 배경(Why)**: 신기술 검토에 드는 시간 문제 제시, "특정 업무에 최적화된 도구가 범용 도구보다 낫다"는 전제를 심사위원 메모 문장으로 깔아둠
3. **에이전트 개요(What)**: 6.5단계 파이프라인 다이어그램, 최적화 포인트 3~4개만 강조 (Scope Calibrator=불필요 검색 제거, Vocabulary Bridge=중복 제거, Conditional Deep Research=조건부 실행), 마무리 문장 "우리는 새로운 정보를 생성하지 않습니다. 가장 적은 비용으로 가장 빠르게 검토합니다."
4. **왜 Liner인가**: Search API(Web/Scholar 분리)가 1·2단계 핵심 근거, Deep Research가 조건부 심화검토의 핵심 (실측 ~59초 언급), Liner 없이는 구조 자체가 성립하지 않음을 명시
5. **아키텍처/데모 예고**: Gap Map + Raw API Stream 병렬 화면 구성 예고, 데모 입력 예시 티저, "지금부터는 슬라이드가 아니라 라이브로 증명합니다" 전환 멘트

남은 확인 사항:
- 데모 전/후 "이 검토를 사람이 했다면 O시간, 우리 에이전트는 O초" 비교 문구 삽입 고려
- Deep Research 스킵 구간에서 "지금 비용이 큰 이 단계는 조건이 안 맞아서 건너뜁니다" 나레이션 준비
- 서프라이즈 태스크 대응 시 "왜 이 경로로 판단했는지"를 자원 절약 관점으로 설명하는 멘트 준비
